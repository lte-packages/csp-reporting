Welcome to the CSP Testing Suite! This application is configured with Content Security Policy settings to help test and verify CSP violation reporting.

📋 About This Demo

This is a Django demo site specifically designed to:

  • Test CSP (Content Security Policy) configuration
  • Verify CSP violation reporting functionality
  • Ensure violations are properly collected and stored
  • Provide a development and testing environment

🔐 Current CSP Configuration

The following CSP directives are active:

  • default-src 'self'
  • script-src 'self' 'unsafe-inline'
  • style-src 'self' 'unsafe-inline'
  • img-src 'self' data: https:
  • font-src 'self'

CSP violations will be reported to /csp/report/

🧪 Testing Tools

Use the following tools to test CSP functionality:

Trigger CSP Violation

Visit the test page to intentionally trigger CSP violations for collection testing.

📊 Monitoring CSP Reports

All CSP violations will be automatically collected and stored in the database. You can:

  • Visit the Django Admin to view collected CSP reports
  • Check the CSPReport model in the admin interface
  • Monitor violation patterns and frequencies
  • Use this data to refine your CSP policies

🚀 Getting Started

  1. Review the current CSP configuration in Django admin or source code
  2. Navigate to the Test Violation page to trigger intentional violations
  3. Check the Django admin to verify violations were reported
  4. Adjust CSP settings as needed and test again
⚠️ Development Environment This demo is running with DEBUG=True and relaxed CSP settings to enable development testing. Do not use this configuration in production.
